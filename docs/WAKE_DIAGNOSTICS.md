# “你好小萌”无响应的本地诊断

当前固件只在 `XY_SLEEP` 且本地提示音及回声尾部保护结束后运行 MultiNet 命令识别。命中“你好小萌”后，先排队播放本地“我在”，再请求连接后端。缺少本地提示不能直接归因于云端延迟。

屏幕的空闲形态目前同时用于 `XY_SLEEP` 和 `XY_LISTENING`。后者表示会话已开启，等待按住 BOOT 说话，并不监听唤醒词。诊断时以遥测 `state` 与 `wake_armed` 事件为准，不能只看屏幕。

## 独立串口诊断

先关闭占用同一串口的桥接或串口监视器；此工具不自动结束其他进程。在仓库根目录运行：

```powershell
& 'D:\conda\envs_dirs\codex\Scripts\python.exe' scripts/diagnose_wake.py --port COM9 --duration 90
```

工具不写串口、不发心跳或模拟唤醒、不连接云端、不复位、不烧录。它只保留白名单中的识别计数、设备状态和提示音事件；不保存 PCM、识别文字、设备 token 或任意日志消息。开头 2 秒用于排空 USB 历史积压，不能把主机收到事件的时间当作声学延迟。

可在读数开始后间隔约 10 秒说三次“你好小萌”，记录每一次的时间和是否听到“我在”。独立诊断没有后端心跳，设备唤醒后约 6 秒会因连接超时回到待机；此时只验收本地唤醒及提示音，不代表整条云端链路通过。Ctrl+C 会结束采集、关闭串口并保存已经收到的脱敏结果。

报告和事件默认写入被 Git 忽略的 `.local`。重放已有日志不打开串口，仍会重新脱敏：

```powershell
& 'D:\conda\envs_dirs\codex\Scripts\python.exe' scripts/diagnose_wake.py --replay .local/wake-events.jsonl
& 'D:\conda\envs_dirs\codex\Scripts\python.exe' -m unittest discover -s tests -p test_wake_diagnostics.py
```

`host_test` 只证明程序触发，不计作真人唤醒；提示播放完成也不等于用户实际听清。没有标记真人尝试的时间，不能用“后台长期零命中”计算漏识别率。设备处于 state 0 仅说明状态允许识别，不单独证明模型已经布防或声学尾部保护已结束。

## 2026-10-12 本地复测

原设备固件未变更，COM9 只读采集确认初始 state 0、麦克风和识别帧持续更新。用户连续三次说出唤醒词，记录到三次真正命中，置信度约 0.222 / 0.326 / 0.219；三次本地提示均播放完成，时长 480 / 479 / 480ms，用户确认全部听到。随后均回待机并重新布防。

这次没有复现旧故障，也未连接云端。历史日志曾有 state 0 下音频/模型持续运行但零命中的片段；用户无法确认旧故障发生于开机后还是未退出的会话中。因此历史漏识别的声学原因仍未确定，不调整阈值或声称问题已经根治。下次复现优先保留带尝试时间的此类脱敏诊断。
